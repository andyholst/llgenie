# scanner-images — proposal

Issue: [#714](https://github.com/asimov-agent/llgenie/issues/714)
Parent: [#713](https://github.com/asimov-agent/llgenie/issues/713)

## Why

The repository has no scanner images at all (`ls containers/` → `agent/ ci-variant/ engines/ test/`),
so any scan would have to install its scanner inside the job: a mutable tool on a mutable base,
with network access while it judges the tree. A scan is only as reproducible as the scanner.

## What Changes

- **One image per scanner** under `containers/scanners/<id>/Dockerfile` (trivy, grype+syft,
  semgrep — Snyk was dropped later, it needed a secret), Wolfi base pinned **by digest**, scanner pinned to an **exact** version.
  (Snyk, since removed, verified its release asset by sha256 because Wolfi never packaged it.)
- **`containers/scanners/digests.json`** — the file the scan workflow reads: pinned version and
  content-hash ref per scanner, generated by `make scanner-digests`.
- **`scripts/scanner_image.py`** — `digest`/`ref`/`build`/`test`/`publish`/`write`/`check`/`ci`.
  The publish policy (push runs publish, `pull_request` runs do not) lives in the script, never in
  a scenario-scoped workflow `if:`.
- **Make targets** `scanner-image`, `test-scanner-image`, `scanner-digests`, `scanner-ref`,
  `publish-scanner-images`, `ci-scanner-images`, `check-scanner-images`; the last is wired into
  `make ci-unit`.
- **CI job `scanner-images`** in `ci.yml` (build + version test on every PR, publish on a push).
- **`docs/SCANNERS.md`** (linked from `README.md`) and `tests/test_scanner_images.py`.

## Not covered

- Running a scan against a repository or image — that is #715 (the scan workflow consumes
  `digests.json`).
- Turning findings into issues (#716) and remediation (#717).
- Retagging upstream scanner images (not used; these are built here).
